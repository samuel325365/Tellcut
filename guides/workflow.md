# Workflow and tools

Follow this wherever a film is made; what makes a good film is in `guides/quality.md`. Each mode's own limits (whether you may run things in the background, how to change a finished project, whether you may export) are in that mode's own instructions; where they differ, the mode's instructions win.

Run every command in the `tellcut/` folder. Look up blocks with `catalog` and cut.ts methods with `cut-api`; **do not read the source code**. The tools print in Chinese (Traditional): where this guide says what to look for in their output, it quotes the Chinese words.

## Commands

| Command | What it does |
|---|---|
| `npm run new -- <id> <folder\|file\|url>... [--size 1080x1920] [--fps 30] [--name name]` | Make a new project (footage may be in any folder: an absolute path such as `D:\Trips\Kyoto`, or a path relative to tellcut/). If the id exists, pick another name; **never add `--force`** (it replaces someone else's project). An animated explainer without footage: `npm run new -- <id> --blank [--size 1080x1920]` |
| `npm run inspect -- <id>` | Footage analysis: one line per source (length, orientation, segments, how the speech starts), the footage overview image, music beats, chapters |
| `npm run inspect -- <id> --source <source>` | One source in detail: scene list, transcript sentence by sentence (with times), a large contact sheet |
| `npm run inspect -- <id> --source <source> --range 5:00-6:30` | Just one stretch: a frame every few seconds, each labelled with source and time, plus that stretch's scenes, transcript and faces (how many, left/centre/right). Use it to find shots in long footage; inspect caches, so rerunning is quick |
| `npm run tellcut -- catalog --find <keyword>` / `catalog <type or handle>` [--project <id>] | Find blocks (names, descriptions and parameters are all searched) / see all of one block's parameters (a handle works too: `catalog MRK-03`); `--project` adds that project's own fx. Without arguments it prints everything (very long) |
| `npm run tellcut -- recipe <name>` / `cut-api` | A recipe's content format and example / the Cut API cheat sheet (one line per cut.ts method) |
| `npm run cut -- <id> [--force] [--no-transcribe]` | Run `projects/<id>/cut.ts` to make the first cut (`--no-transcribe`: do not wait for transcripts; avoids transcribing every source when the server is not running) |
| `npm run check -- <id> [--quick] [--sheet]` | A text report on the result: black frames, offline sources, over length, empty captions, captions not matching speech, music too short, text outside the safe area or overlapping, caption letters too small (under 48 px), clipping, silence, the footage's own black bars showing, clips whose head or tail runs into the source's previous or next shot (those frames often carry the source's text; move the in/out points as it says), video frames running off screen; the footage's own text showing on screen (labels, titles, watermarks; read by text recognition; text cut by the frame edge is a warning, the rest is listed in one note; shop signs and menus may stay); the film's length or ratio outside the preset it was made from, or outside the length and ratio picked in its form (a warning: fine when the user asked for it); pacing: short-form with neither text nor speech in the first second, text cards too short to read, photos held too long without moving, several shots in a row of the same length. `--quick` checks only the project file (instant); `--sheet` adds one contact sheet of the whole film (without `--sheet` the old sheet is deleted, so the sheet you see is always the latest) |
| `npm run tellcut -- frames <id> [--full] --at 1.5,3` | Frames as PNG (long side 960: enough for layout, cuts and captions; add `--full` for full size only to check fine text, about 4× the cost: vertical 540×960 is about 700 tokens, 1080×1920 about 2,700) |
| `npm run voice -- <id>` / `npm run score -- --styles <id>` | Narration voice / list music styles (see "Narration and music") |
| `npm run tellcut -- assets …` | Outside assets: music, sound effects, pictures, maps, fact checks (see "Outside assets") |
| `npm run tellcut -- logo <id> <file> [--name <name>]` | A brand logo (SVG, PNG, JPG, WebP) into `media/brand/`: whether it extrudes (an SVG of filled shapes) or becomes a cut-out plate, its colours (for `c.theme`), the `common.logo` line to use, and two previews (in 3D and flat) to look at once, and a warning when its main colour hardly shows on the background (then give `common.logo` a `bg`, or use a light/dark version of the logo) |
| `npm run tellcut -- seams <id>` | Every `common.dolly` handoff: the 3D frame and the clip on each side of it: average colour within 1 and pixel by pixel at least 30 dB PSNR (a small position or crop jump), and no transition, opacity, freeze, defocus or shake on the clip |

## Look at pictures sparingly

Every picture is expensive, and the earlier you look the more it costs (every later step reads it again). **The pictures for one film follow the 「看圖預算」 (picture budget) on the second line of `inspect`** (worked out from the footage: overview, closer looks at sources (long footage and footage with many shots get more `--range`), check sheets, frames; plus 2 for each new fx). It is a guide, not a hard limit: when you go over it, be able to say why (for example, the shot you need is still not found), and never just look again. A film with no footage and no inspect: about 10 pictures, plus 2 for each new fx; a preset may allow more (it says so in its own rules).

- Footage: look at `inspect`'s footage overview first (one row per source), and run `inspect --source` only on sources you will use; for long footage, find shots with `--range`.
- Picking outside assets: look at the one contact sheet `assets search` prints; do not open them one by one.
- The result: use `check`'s text report first; for the whole film, the one contact sheet of `check --sheet`; `frames` only to confirm a detail.
- When a command prints a lot, read only the end or the part you need; read long transcripts with `--range` for the stretch you need. Never reread a large file you have already read.

## Presets (picked on the home page)

The preset the user picked on the home page (`guides/presets/<id>/preset.md`; the user's own are in `projects/_presets/my-*/`) is put in front of the message by the server, and a project made with a preset records it in `meta.preset`. A preset is the default direction of the film (ratio, length, framing, styles): follow it when writing the storyboard; what the user says comes first.

The custom preset's form shows up as "Options the user set" in the preset block (and in the project line later); they are more specific than a preset's defaults, but what the user says in the message still comes first.

## Steps for a new film

1. `npm run new -- <id> <footage path>...` (vertical short-form: add `--size 1080x1920`).
2. `npm run inspect -- <id>`: read the text and the footage overview first; run `--source` (scenes, transcript) only on sources you mean to use.
3. **Write a text storyboard**: which segments, their order and length, the captions and titles, the mood of the music. Write it in `projects/<id>/storyboard.md` (later changes, and anyone taking over, go by it).
   - **First decide which genre the film is**: read `guides/genres/README.md` (every genre in one line, the editing styles, the ratios with their safe areas), choose one, then read its card `guides/genres/<id>.md`. The storyboard **answers each "must-have" one by one** (where and how each is done; if one cannot be, say why), avoids the "pitfalls", and picks its editing style from those the card recommends; for the layout use the card's line for the film's ratio and that ratio's row in the README's "Ratios".
   - **Long talking footage** (interviews, podcasts, vlogs, courses, live streams): first list 5–8 candidate stretches from the transcript, one line each: source time, what is said, a score (does the opening grab / does it stand on its own / does it carry information or feeling / does it end on the point). One that does not **stand on its own** ("he", "this" pointing back to something said before, needing what came before, a long build-up, cut off before reaching the point) is widened forward or back, or dropped. Choose by score, not by order of appearance; this step reads only the transcript, no pictures.
   - The storyboard's first line gives the **target length in seconds** and the **through-line** (and how it shows on screen); see `guides/quality.md`.
   - Mark every element "library" (ready in `catalog`), "tuned" (ready, with parameters changed) or "new" (nothing fits, written as this project's fx; see "The project's own effects (fx)").
4. Write `projects/<id>/cut.ts`: use a recipe when one fits (see "Recipes"); by hand, look methods up in `cut-api`; the format is `export default async function (c: Cut) { … }`.
   - A main track with gaps left on purpose (3D over nothing, a title on black after `c.at()`) is saved as an ordinary track, not magnetic: cut prints a note, and editing in the editor then never closes the gaps.
5. `npm run cut -- <id>`, then `npm run check -- <id>`: on errors, change cut.ts and rerun (`cut --force`) until there are none; handle warnings as fits and say why. `--force` rebuilds the whole timeline from cut.ts: use it only while making the first cut, never after the user has edited in the editor.
6. Finally `npm run check -- <id> --sheet`, and look at the sheet and fix as in `guides/quality.md`'s "Before delivering, look with a critical eye".
7. **List promotion candidates**: which of this film's new fx and music styles, made generic with parameters, other films could use too (for example a "depth gauge" could become a generic "value meter"). One line each: the file, what it does, and which hard-wired things would become parameters. Promotion is done by whoever maintains Tellcut, in Claude Code (`npm run promote` / `promote-style`); if nothing is worth promoting, say so.

## The project's own effects (fx)

What the library and tuned blocks cannot do, or not well enough, is written new. First make sure with `catalog --find` that nothing can really do it well.

- File: `projects/<id>/fx/<name>.js`, an ES module whose `export default` is an array of ItemTypes. Register it in cut.ts with `c.fx('fx/<name>.js')`, then put it on the timeline with `c.effect('fx.<type>', { at, len, ...params })` (then `npm run cut -- <id> --force`). See `tools/fx-example/ring.js` for an example.
- The fx module can hold its own sound effects too: add `export const sfx = [{ type: 'fx.<name>', label, doc, params, duration: (p) => seconds, synth(ctx, bus, at, p) { … } }]` (`synth` fills samples with `ctx.createBuffer`, connects to `bus.out` and starts at `at`; the samples depend only on the parameters, and randomness again uses a seeded LCG), then place them like shared sounds with `c.sfx('fx.<name>', { at, len, gain })`. A module with only sounds may leave out `export default`.
- The type always starts with `fx.`. Required fields: `type, label, kind` (`'overlay'` or `'scene'`; the layer does not follow kind: for a backdrop under the video (paper, a stage), add `layer: 'under'` when placing it)`, doc` (one line)`, params, build(ctx), draw(ctx, state)`. `build` makes its DOM / canvas in `ctx.root` and returns the state; `draw` draws the current frame from `ctx.local` (seconds into the item), `ctx.dur`, `ctx.params` and `ctx.W/H` only.
- Text on a canvas: load fonts in `ready(state)` (`return document.fonts.load('700 60px "Noto Sans TC"', text to draw)`, one per weight and family, joined with `Promise.all`), **never in `build`**: at that point the player's font table may not be registered yet, so loading does nothing and the export falls back to another font. Noto Sans TC: use 400 or 700, never 500 (one line comes out in mixed weights). For English or other Latin text use a Latin face (see the fonts under "Shared blocks and theme").
- **Words in an fx** are in the film's language: write them as parameters (in that language), never hard-wired in another one.
- **Determinism**: the picture may depend on time alone. No `Math.random`, `Date`, `performance`, `setTimeout/setInterval`, `requestAnimationFrame`, `fetch` or `eval`, and no importing packages (relative paths only). For randomness, write a seeded LCG in the file (for example `let s = seed; const rnd = () => (s = (s * 16807) % 2147483647) / 2147483647;`, restarting from the seed on every draw). Drawing the same time twice must give exactly the same picture.
- **3D with three.js**: add `three: true` to the item type; then `ctx.three` holds `THREE`, `addons` (RoundedBoxGeometry, RoomEnvironment, SVGLoader), `render(scene, camera, W, H, { toneMapping: true | false | 'neutral' | 'none', background, bloom })` (the one shared renderer: copy its canvas onto your own canvas right after; `bloom: <strength>` glows the bright parts, only for 3D without footage, and is ignored with `toneMapping: false`), `mediaTexture(el)`, `fillDistance(faceH, fov)`, `coverUv(...)`, `environment()` (soft reflections for `scene.environment`) and `loadFont('Inter-700.ttf')` in `ready` ( `has(ch)`, `advance(ch, em)`, `shapes(ch, em)` give Latin letters to extrude with `new THREE.ExtrudeGeometry(shapes, …)`; other scripts are drawn on a canvas texture). Never import three. Build the scene once in `build`; in `draw` set the camera first (from `ctx.local` alone), then pose the objects (anything that turns to face the camera uses this frame's camera), render and copy (`render` gives null without WebGL2: draw something flat then). Load textures and fonts in `ready` (text on a texture is drawn there, after `document.fonts.load`). In `hide` only release your canvas (width and height 0) and size it again at the top of `draw`: the item draws again when the playhead comes back. Free the geometries, materials and textures in `dispose(state)`, which the stage calls when it drops the item (an edit rebuilds it, it is removed, another project loads). A clip on a 3D surface: `mediaTexture(ctx.media.video(ref, hiddenHolder, ctx.local))` called in every `draw`, uploaded with `update()` in `late(ctx, state)` (it runs after the videos are seeked), rendered with `toneMapping: false`, no bloom or particles over the footage; **the type must also declare that clip in `media(item, project) { return { videos: [ref], stills: [] } }` with exactly the same ref** (`{ source, in, out: in + (item.end - item.start), speed: 1, interp: 'none' }`), or the export cannot find it (the preview works without, the export fails). **Switching between real footage and 3D always goes through `c.dolly`** (the shared 3D frame push / pull), never through your own fx. Example: `tools/fx-example/spin3d.js`.
- Always run `npm run check -- <id>` afterwards: it scans for the forbidden things above and failed loads, and actually draws the fx twice at the same time to compare. Fix until there are no errors.

## Shared blocks and theme (common.*)

- Shared blocks (`common.*`) are ready-made blocks for any project: **use them when they fit; never write a new fx for the same effect**. The index below gives only handles and names (without the `common.` prefix); the categories are for finding things, not a suggestion to use one of each.
- **Handles**: every shared block, sound effect, music style and recipe has a gallery handle (`MRK-03`, `SFX-HIT-02`, `MUS-07`, `RCP-01`, clip effects `CLP-01`); in the index each category's prefix is in brackets, followed by numbers (`03 stamp` under stickers and marks is `MRK-03`). When the user says a handle, look it up with `npm run tellcut -- catalog <handle>` (`mrk-3` and `MRK3` work too). Handles are only for talking: cut.ts, proposals and project.json always use the type id (`common.stamp`), and in replies write "`MRK-03` stamp" so the user can match the gallery.
- **Look before use**: `npm run tellcut -- catalog --find <keyword>` searches names, descriptions and parameter options (for example `--find receipt`, `--find route`, `--find handwriting`; several words separated by spaces must all match), one candidate per line; once chosen, `catalog <type or handle>` shows all its parameters (every `look` / `mode` is described there). The whole `catalog` is very long; never read all of it.
- **Words inside blocks**: many blocks have Chinese words as defaults (labels, buttons, UI text such as 已讀, 搜尋中…, dates, stamp words). When the film is not in Chinese, set every visible word parameter in the film's language; `catalog <type>` lists each block's text parameters and their defaults.
- **Fonts** loaded for blocks and fx: Chinese Noto Sans TC (400/700/900), Noto Serif TC, LXGW WenKai TC (handwriting), Huninn (rounded); Japanese Noto Sans JP (400/500/700/900); Latin Inter (300, 400, 600, 700), Playfair Display, Cormorant Garamond (serif display), JetBrains Mono, VT323 (pixel). Noto Sans TC's Latin letters work for plain captions; for English display type pick a Latin face that suits the theme (`c.theme({ fonts: { display: 'Playfair Display' } })`). A film whose on-screen text is Japanese sets `c.theme({ fonts: { display: 'Noto Sans JP', body: 'Noto Sans JP' } })` (and `font: 'Noto Sans JP'` on core.caption): Noto Sans TC draws Japanese kanji in their Chinese forms. Text drawn on a canvas loads it in `ready` like any face.

- Used together with the Cut API: a main-track clip playing inside a frame uses `postcardWindow` / `frameWindow` / `duoWindow` / `casefileWindow` / `magazineWindow` / `outroWindow` (the episode end card), inside a chat bubble `chatWindow`, in the search page's video window `searchWindow`, on a phone screen `screenFrame(width, height)` (imported from `@tellcut/plugin-common`, given as the clip's `frame`); `c.bands` (horizontal footage cut into bands stacked in a vertical frame), `c.view` (one shot cropped into several virtual cameras); usage in `cut-api`. Music styles: see "Narration and music".
- Their colours, fonts, safe area, corner radius and stroke all follow the project theme. Set it once at the top of cut.ts: `c.theme({ palette: { accent: '#ff4d4f', hl: '#ffe14d', ink: '#1a1a1a', paper: '#fff8ec' }, fonts: { display: 'Noto Sans TC' }, safe: { bottom: 0.22 }, radius: 24, stroke: 8 })`, filling only the fields to change. An item's own parameters win over the theme.
- Position: by default these blocks keep clear of short-video interfaces (the theme's safe area: vertical, 11.5% at the top, 22% at the bottom, 12% left and right, where the platform's interface covers the picture; check uses the same numbers for its 「平台介面區」 (platform interface area)); to move one, use the item's `transform`, never force numbers to cover the safe area.
- On the timeline: picture blocks with `c.effect('common.slam', { at, len, text: '…' })`; to sit above the captions (film texture, flashes) add `layer: 'top'`; sounds with `c.sfx('common.beep', { at, len, gain, ...params })` (`common.beep`'s length matches the word it bleeps). These methods make the tracks they need. `c.effect(..., { transform: { x, y, scale } })` positions an item (for example to move a caption up).
- **Sound effects**: pick from the sound index above first (find with `catalog --find ding`, `--find water`). A run of dings climbs the scale one step at a time: `common.ding` / `common.xylo` with the same `pitch` (the tonic) and `step: 0, 1, 2…` (`scale: 'pentatonic'` for the pentatonic scale); set pitch to the tonic of the music's key. Synthesise only sounds the library really lacks: short ones as `export const sfx` in the project's fx module (see "The project's own effects (fx)"), or (developer mode only: the page chat may write only cut.ts, fx, score, narration, storyboard and proposal files, and cannot run node) written as WAV by a script (for example `sfx/make.mjs` → `media/sfx/*.wav`) and placed with `c.sfxFile('media/sfx/ding.wav', { at, gain })`. **Never** open a separate music track for your own sound files, mix the effects into one long file, or write them into a music style: they would be treated as music (ducked, and check's narration / music rules), and moving one would mean remaking it all. `c.sfx` and `c.sfxFile` both go on the one SFX track, which is not ducked.
- **Cut the pauses out of talking clips first**: `const ids = c.tighten(c.clip(source, { from, len }))` shrinks gaps over 0.6 s inside speech to 0.3 s (the sound is cut with it, never through a word; on 30 s of raw talk it saved about 19% on average). Use it right after that clip, before captions; then pass the returned `ids` to `speechCaptions` and `censorSpeech` (a sentence across a cut shows only once). To keep a pause (waiting for a laugh, for feeling), do not tighten. The `hook` recipe tightens every segment by default.
- **Talking heads, podcasts, personal takes**: caption speech with `c.speechCaptions(clip, { type: 'common.caption', karaoke: true })`: the word being said lights up (from the transcript's timing). **Two or more people talking**: add `speakers: [[from, to, 1|2|3], …]` (source seconds; judge who speaks from the transcript and the picture) and `names: ['', 'Amy', 'Ben']`: each person's captions get their own colour with the name above, and no caption runs across a change of speaker. The transcript has no speaker information; if you cannot tell, do not force a split. Only the words the clip plays are captioned (a sentence its in or out point cuts keeps the part inside); `drop: ['um', 'uh']` leaves fillers out, `pause: 0.45` starts a new caption where the speaker stops, `maxChars: 26` caps a caption's length; two captions are never up at once. Do not build captions from transcript.json yourself.
- **Captions you write yourself** (a translation, a cleaned-up line, a song): `c.lines(clip, [['1:13.85', '1:15.25', 'It was supposed to be a beautiful day.'], …], { type: 'common.caption', hold: 0.5 })`, timed in the source's own seconds (as the transcript and the player show them; '1:23.5' or 83.5), hung on the clip; a line outside the clip is an error. A source moment's place in the film (to time a sticker or a sound to a line): `c.filmTime(clip, '6:16.45')`.
- **J-cut / L-cut**: `c.audio(source, { from, len, at })` puts a stretch of the source's sound alone at film time `at` (the next shot's sound coming in before its picture, a voice carrying on over the next shot); give the clip whose sound it overlaps `sound: false` or start it later, so no words play twice. Do not cut source sound into WAV files for this.
- To bleep a word: `c.censorSpeech(clipId, 'word', { follow: true })` does it all (finds when it is said, cuts the original sound, adds the beep, and puts a censor sticker on the speaker's mouth that follows it, all attached to that clip); captions blank it with `speechCaptions`' `censor: ['word']`. The footage's burned-in text may give it away; see "The footage's burned-in text".
- **Stickers that follow a person**: `c.effect('common.emoji', { at, len, char: '🤐', follow: 'mouth' })` (or `follow: 'face'`); with several people on screen choose with `who: 'left' | 'right' | 'largest' | 'center'`. The position is worked out on save, and `npm run cut`'s output says whether it followed.
- **A film whose through-line is "more and more…"** (diving deeper, climbing higher, a countdown): `common.meter` and `common.ambient` take the same `stops` (`"0:0, 4.2:70, 9.6:332, 30:10928:s"` = at which second which value, `:s` jumps straight there); give both the same variable in cut.ts and the number and the background change together; with a very wide range, give both `scale: 'log'` and the same `max`.
- **Camera shake**: `c.shake(at, { dur: 0.4, px: 24 })` shakes the clip playing at that moment (a slam of text, a hit, a punchline). For the `hook` recipe's opening, add `hook: { shake: true }` (no shake by default).
- Horizontal footage in a vertical film without a crop is framed on faces automatically on save (the output lists them); to choose the focus, give `crop` / the recipe's `focus` yourself. A crop can be written short: `crop: { x: 0.4, push: 1.05 }` (start at x, y, zoom — default the centre at 1 — and end zoomed 1.05×), `crop: { x: 0.3, zoom: 1.2, to: { x: 0.5 } }` (a pan); `from` can be written as the player shows it, `from: '1:23.5'`.

## Layout recipe (panel layout, sticker / card look)

- One line sets the layout: `c.panel({ radius: 28 })` (without a frame it is chosen from the film's ratio; to set it yourself give `frame: [x, y, width, height]` as **fractions** of the picture (0–1), not pixels), **before the first `c.clip`**. Main-track clips then shrink into this rounded rectangle, and on save `common.backdrop` (checkered by default) goes underneath and `common.panel` (thick frame with tape) on top. `backdrop` / `border` take parameters to override (`backdrop: { pattern: 'dots' }`), or `false` for none.
- Horizontal footage in a near-square panel: choose the focus with `crop`'s x (look at thumbnails for where the people are); do not squeeze the whole frame in.
- **Horizontal footage in a vertical film** always leaves a big gap above and below the panel: use `backdrop: 'blur'` (each clip's own picture enlarged, blurred and darkened to fill the frame, changing with the clip), never large flat colour or just a starfield; use the default checks only for a film that wants a pattern look.
- Above the panel: `common.badge` (`label: 'No.1'`, `plate: 'shop name'`, top left by default), `common.tag` (`tags: 'tag one,tag two'`, under the badge at y≈0.14); below the panel the captions, with `common.caption`'s `style: 'bubble'` recommended.
- The sticker version of slammed text is `common.burst` (a jagged burst with text); for more punch put a `common.speedlines` before it (same centre). Chapter progress with `common.progress` `mode: 'dots'`; `icons: '🍗,🥟,🍬'` turns each dot into an icon; to write chapter names use `mode: 'tabs'` (`labels: 'Dry,Wet,Batter'`, one item per chapter with `step` its number; done chapters tick themselves).
- **Step-by-step tutorials / recipes**: one `common.card` per step (`no`, `title`, `detail`, `tip`; the first with `no: ''` is the cover). The picture window draws an `emoji` by default; to draw this film's own illustration, write an fx (drawing its own `ctx.W×ctx.H` as usual) and put it in the window with the card's `art: 'fx.<your id>', artParams: {…}`; the card handles turning, dealing and tilting, so do not redraw the card in the fx.
- **A film whose state changes stage by stage** (catches, scores, a collection): one `common.scoreboard` item per state, `values` the new values, `pop` the cell that changed in this stage, `note` a small note; the first stage with `enter: true` slides in.
- The panel's x,y,w,h must equal the video's frame; check warns when they differ. With `c.panel` both match by themselves.

## The footage's burned-in text (subtitles, titles)

- `inspect`'s footage overview adds a line under a source with burned-in text, 「燒字：畫面下方…有原片自己的字幕」, and `inspect --source <source>` lists when it appears. **When you see that line, deal with it**: our captions would sit on top of it, and a word to bleep may be written out in it.
- Ways round it (pick one): `c.clip(source, { ..., avoidBurned: true })` zooms in and moves the focus up to crop the subtitle band out of the picture (the detected subtitle times and 3 s either side count; if 2.2× cannot clear it, it prints a note and changes nothing); or put our captions at the top (`position: 'top'`); or choose times / shots without text.
- `check` reports in the picture layer: our text over the burned-in text, words to blank that the source burns in at the same time, bleeped words still written in the source's subtitles, and the footage's own text on screen (labels, titles, watermarks, read by text recognition). Text recognition cannot read fancy display lettering and may miss text that flashes by; still look at the thumbnails once for footage with its own text.
- **At cuts**: a clip's in or out point one or two frames off runs into the source's previous or next shot, and that frame often carries the source's big text. `check` (`--quick` too) catches it from the source's shot changes; move the in/out points as it says. It cannot catch very slow dissolves.

## Narration and music

**Narration** (edge-tts, needs the internet):
1. Write `projects/<id>/narration.json`: the narration is in the same language as the captions (as the conversation says, otherwise the UI language), with a `voice` of that language: `{ "voice": "en-US-AvaNeural", "rate": 5, "pron": {}, "scenes": [{ "id": "s01", "text": "The first line." }, …] }` (Traditional Chinese, for example `zh-TW-HsiaoChenNeural`). One or two sentences per scene; `pron` is sound-alike replacements only the speech engine sees (for example `{ "一行": "一航" }`, or a respelling for an English name it misreads), and the captions still show the original. Chinese characters with several readings are easily misread (著, 乾, 行, 重, 長…); after writing, swap suspicious ones for sound-alikes.
2. `npm run voice -- <id>`: makes `media/voice/<scene>.wav` and phrase timings for each scene; unchanged scenes are not remade.
3. cut.ts: `const v = c.voice('s01', { at })` puts it on the narration track (without moving the cursor), and `c.voiceCaptions(v, { style: 'bubble' })` makes captions from the phrases (timed automatically). Fit the picture to the narration: look at `v.end`.

**Music**:
- See the styles first: `npm run score -- --styles <id>` (five built-in, the style library, and this project's own). In cut.ts `c.score('<style>', { seed, key, bpm, gain })`: composed on save to the film's length, the last chord landing exactly at the end; beats start at 0 s, and `c.beatLen(4)` still puts cuts on the beat (library and project styles too, without giving `bpm`); `c.beats(3)` is three beats in seconds, for lengths counted in beats. A project style that answers moments of the film reads them from `ctx.cues`, given as `c.score('<style>', { cues: { lift: 43.2 } })` (film seconds by name). Use `c.music()` only for a ready music file (for example real-instrument music downloaded with `assets get`; see "Outside assets"); one or the other.
- Pick library styles by use (details with `--styles`; all lay out sections by the film's length and finish in the last bar at any length):
  - Food, shopping, lists: `market-groove` (night market), `receipt-hop` (receipts, bookkeeping), `queue-call` (queueing for a famous shop, number N), `walking-pizz` (walking pizzicato: map routes, eating on foot), `steelpan-bossa` (summer steel pan: ice desserts, the seaside; mostly a thin beat left for talk)
  - Gentle, handmade, memories, bedtime: `garden-folk` (afternoon kitchen), `postcard-felt` (felt piano), `lullaby-box` (night-light music box: parenting, bedtime; turns minor in the middle with a heartbeat)
  - Funny, games, kinetic type: `mischief` (sneaky plucks), `chiptune` (8-bit: capsule toys, gacha, games), `funk-minor` (minor funk: quotes, kinetic type), `bout-bell` (boxing ring: debates, two sides compared)
  - Fast cutting: `rail-beat`; interview quotes: `quote-drop`; a bed far under talk (podcast and interview clips): `night-studio` (soft electric-piano chords, pad and sub; gain about -19)
  - Celebrations (birthdays, weddings, graduations, a surprise): `candle-glow` (warm piano, pad and celesta; follows the film through `cues`: `low` turns minor, `bright` blooms back, `play`, `wait` holds a suspended chord before a surprise, `shout` falls silent for the crowd, `party` grooves, `quiet` leaves only a pad while the room sings, `tender` is piano alone)
  - Culture, history: `guzheng-pop` (guzheng pentatonic with light electronics: Hakka, Taiwanese tradition, an East Asian feel), `hijaz-route` (oud and frame drum in the Hijaz scale: history, maps, the Silk Road, spices, the Middle East)
- During narration and **while someone is talking in a clip**, the music ducks about 10 dB by itself (from the transcript; `c.duck(-14)` sets the depth, `c.duck(false)` turns it off, `c.duck(-10, { speech: false })` ducks only for narration). A clip whose own sound is at -20 dB or lower (room tone under a montage) does not duck it; `c.clip(…, { duck: false })` keeps a clip from ducking it, `duck: true` makes a quiet one duck it, `duck: -6` ducks less under that clip (an instructor's countdown, someone who is not the subject). Do not turn ducking off to draw it by hand with `c.level`. So set the music's `gain` for **when nobody is talking**, about -8 to -10; do not go below -20 for fear of covering speech (then the music cannot be heard when nobody talks). check warns when narration is covered by music.
- To let the music drop out at an emotional peak: `c.dip(at, { len: 1.5, db: -18 })`. To shape its level over the whole film (quiet intro, full at the reveal, down for the end card): `c.level([[0, 0.6], [12, 1], [55, 0.4]])`, gain multiples 0–1.5 eased from point to point; ducking and dips still go lower where they say.
- **When no style fits, write a new one**: `projects/<id>/score/<style id>.js`, in the format of `tellcut/score-library/README.md` (`build(ctx)` returns the notes, `voices` can define its own instruments, randomness only through `ctx.rng()`, no importing packages). Afterwards run `npm run score -- --styles <id>` to confirm it loads and `npm run check -- <id>` to confirm nothing breaks the rules. A good project style can be a promotion candidate.

## Outside assets

When the footage is not enough, fetch from outside, **always with these commands** (never write your own downloader): stretches with no footage, missing places or empty scenes, stock footage of everyday life and work (Pixabay), real ambience or foley, real instruments when the synthesised score is too plain, maps or routes, checking the facts in narration, character pictures or data for theme films (Pokémon, Nintendo, Harry Potter, anime, Steam games, countries, recipes).

1. `npm run tellcut -- assets sources`: the sources usable now, one per line. Read how to query a source, its conditions and pitfalls with `assets source <source>` before using it.
2. `assets search <keyword> [--kind audio|music|image|video] [--source <source>] [--min-sec n] [--max-sec n] [--ratio 9:16] [--opt k=v]`: pictures come with one contact sheet; choose from it. Most sources want **English** keywords.
3. `assets get <project> <number> [<number> …] [--from seconds --len seconds]` (several numbers in one call, for example the photos of a wall; `--from`/`--len` one at a time): downloads into the project, registers it, and prints the cut.ts usage (`c.music(…)` / `c.sfxFile(…)` / `c.photo(…)` / `c.clip(…)`); place it as shown. Videos (NASA, Pixabay, Steam trailers) are registered as video sources: run `npm run inspect -- <project>` first, then choose stretches; for long ones take only a stretch with `--from` / `--len`. Sound is **only peak-limited, never made louder**, and `sfxFile` is not ducked: set the level yourself with `gain`; a very quiet one prints an extra line 「很小聲」 (very quiet) with how many dB to add.
4. Maps: `assets map <project> --at <place>`, or `--from <place> --to <place> [--mode straight]`, `--style street|satellite|light|dark`. Places outside Taiwan in English or the local spelling (Kraków); coordinates with `assets data maps <place>`. Places and both ends of a route get pins by default; for a clean base map (to zoom into, or with pins drawn by an fx) add `--no-pin`; never retouch the picture. The `z` printed is the number for `--zoom` (add or subtract from it for the same place nearer or farther). The map's coordinates and zoom are kept with the asset: to push in and out on a map, draw routes, drop pins, or open and close a corner minimap, use `common.mapcam` (`source` the asset id printed, pictures of the same place at other zooms in `layers`; for pictures downloaded earlier without that record, supply `at` + `zoom`, or rerun the same `assets map` command); from the globe down to a country use `common.worldmap`, and switch to mapcam for closer. Each of these commands prints its usage with --help.
5. Facts: `assets data wikimedia <article>` (a summary of the Chinese Wikipedia article, in Traditional Chinese). Theme data comes from the matching source's `assets data` (`assets sources` marks which can be queried), for example `assets data pokeapi Charizard` (stats, Pokédex text), `assets data countries Japan` (population, area, currency), `assets data steam top` (concurrent-player ranking). Check numbers, years and claims in narration first; rewrite source text in your own words in the film's language, never translate it line by line.

- A source missing from `assets sources`, or a search saying it is unavailable for now: use another source or synthesise; do not retry again and again, and do not change the script for it. The `npm run sources` in such messages is for the user to see why in a terminal; the page chat cannot run it, so just tell the user they can.
- Credits are written to `media/CREDITS.md` automatically: after every download, `npm run cut` and export they are rewritten from the timeline, with what the film uses first and downloads it does not use under 「下載了但片裡沒用到」 (downloaded but not used); each line once (`assets credits <project>` rewrites and prints them any time). Tell the user when a licence is NC (non-commercial) or **personal use only** (BBC, the Incompetech mirror, EOX satellite maps), or the copyright belongs to a game or anime company (pictures of Pokémon, Nintendo, Harry Potter, anime, Steam).

## Recipes (a starting point, not a finished film)

Before a new film, decide whether it is one of the four kinds below. If it is, **start from the recipe**: fill one data object in cut.ts and the layout, captions, sound effects, music, ducking and ending are laid out, saving the turns of writing them by hand. **But a recipe is only a generic skeleton**: this film's own through-line and the mood of its subject are not done for you; after the recipe, make them with the theme, `c.effect` / `c.update` and new fx.
- `travel` narrated travel (scene by scene, narration over shots), `hook` hook short (talking footage, panel layout, badges, bleeps, pauses cut), `montage` music montage (shots cut on the beat; `mood` sets how long shots stay, alternating long and short by itself; mark the most important shots `hero`, and give the emotional peak a `drop` so the music drops out for two beats), `brand` brand film (hook, wall of photos, what they do, proof, we are, 3D logo on bars of cinematic music; it checks there is enough distinct footage).
- `npm run tellcut -- recipe <name>` prints its content format and a filled-in example; fill it in that shape, and fields left out take defaults.
- cut.ts: `export default async function (c) { c.recipe('travel', { … }); }`. After the recipe you can call other methods to add more (for example a `common.sparkle`); everything it makes is ordinary timeline items.
- When the recipe content has an error, the message names the field.
- Only for films outside the four (for example an explainer without footage: `new --blank` first) write cut.ts by hand (methods in `cut-api`; speech captions `c.speechCaptions` and bleeps `c.censorSpeech`, the same as the recipes use).
