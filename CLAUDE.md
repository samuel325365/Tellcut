# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Tellcut: a video editor used in a local browser (Node 24 + TypeScript, **Windows only**), plus a "generation toolkit" for Claude (new → inspect → cut → check → export). How to use it, the full command table and the project folder format are in [docs/reference.md](docs/reference.md) (the README is the introduction for everyone); this file only covers what is hard to see from reading the code.

- The git root is `tellcut/` itself (branch `main`); commit paths have no `tellcut/` prefix.
- Public docs are in English; code comments are in English. The one exception is `README.zh-TW.md`, the Traditional Chinese README: keep it in sync with `README.md` (change one, change the other). Pictures for the README are in `docs/readme/` (sources in `docs/readme/CREDITS.md`). UI text goes through the three dictionaries in `apps/editor/src/i18n/` (zh / en / ja, with the same keys; the editor's labels are always English, while hints, tips and status text follow the language); never hard-code text in a component. The page chat replies in the UI language.

## Common commands

```
npm run server                         # http://127.0.0.1:5174/editor/ (local connections only; -- --port 5200 for another port)
npm test                               # everything (the fast and browser groups, see vitest.workspace.ts)
npm run test:fast                      # the group that needs no Chrome; run this first after a change
npm run test:browser                   # export, check's picture layer, golden, editor e2e (at most two files at once)
npx vitest run tools/cut/cut.test.ts   # one test file; add -t "<name>" for one case
npm run typecheck
npm run build:player && npm run build:editor
npm run golden -- [--update <name prefix>] # golden images of the shared blocks; --update takes one prefix at a time, and look at the images after updating
npm run setup / npm run doctor         # install the outside dependencies into vendor/, .venv, models/; when the environment misbehaves, run doctor first
```

## Architecture

**One player, four uses.** `apps/player` is the only picture implementation: the editor preview (an iframe, the project passed in by postMessage), export, `check`'s picture layer and the golden images all run it. Export: `media-node/prepare.ts` first trims the pieces the project uses into `projects/<id>/cache/`; `media-node/render.ts` serves the tellcut folder with a static server, opens the player with `?mode=render` in headless Chrome, calls `window.__tellcut.frame(n)` frame by frame and feeds the screenshots to ffmpeg; the WebAudio mix is rendered offline and then muxed into the MP4.
→ **After changing `packages/*/src` or `apps/player/src`, always `npm run build:player`**: export, check, frames and golden all use the built files. Without a rebuild, golden falsely reports "all match"; check rebuilds by itself when it finds the build out of date (about 4 s; `--quick` doesn't), and only reports an error if the rebuild fails.

**Engine (`packages/engine`)**: `schema.ts` (zod, the single source of truth for `project.json`), the `stage.ts` compositor (one layer per item; `draw(t)` is a pure function of t — a block may not depend on the previous frame's state or on randomness; check draws the same time twice and compares PSNR), `motion.ts` the springs and easings every item gets as `ctx.motion` (thin wrappers over motion-dom / motion-utils, in seconds; Motion's `animate()` is not used, it runs on the frame loop and lags a seek by one rAF), `commands/` the edit commands, `audio/` the mix plan.

**Blocks (ItemType, interface in `engine/src/plugin.ts`) come in three layers:**
1. core: `engine/src/core.ts`
2. common: `packages/plugin-common` (`common.*`, DOM text, sized by min(W,H)/1080 (exception: the font sizes of `common.caption`, header, meter, progress, slam, stamp, tag and tripclock are a percentage of the frame height, and their labels say 「畫面高 %」), positioned within the theme's safe area)
3. a project's own fx: `projects/<id>/fx/*.js` — plain ES modules, default export `ItemType[]`, ids `fx.*`, **may not import packages**, listed in `project.json`'s `meta.fx`; loaded in the browser by `plugins/src/browser-fx.ts` and in Node by media-node.

**3D (three.js)**: blocks and fx that use three are marked `three: true` and get the toolkit from `ctx.three` (`ThreeKit` in `plugin-common/src/three/kit.ts`: the shared renderer, video textures, `coverUv`, `fillDistance`, and the ready-made parts of `three/parts.ts`: `videoSlab`, `glassBar`, `dust`, `floor`). three is only loaded dynamically in `plugin-common/src/three/load.ts`, and the player loads it only when `usesThree` is true (the main chunk has no three; `three/imports.test.ts` guards this). Blocks that read video frames upload the texture in `late()` (`drawFrame`: draw → wait for the video to seek → late); GPU resources are freed in `dispose(state)` (called when the stage drops an item: rebuild after an edit, delete, switching project), while `hide` only lets go of the canvas; video textures are always drawn to a 2D canvas first, because headless Chrome gives WebGL a black `<video>` directly. The hand-off between live footage and 3D uses `common.dolly` / `c.dolly`; `npm run tellcut -- seams <id>` measures the hand-off frame.

`packages/plugins` is the one plugin list shared by player, editor, server and tools. Parameter precedence: item params > the project theme (the path `ParamDef.theme` points to) > the default.

**Promoting fx to a shared block** (`npm run promote` is only tested on fixtures; in practice it is mostly done by hand): write `packages/plugin-common/src/<name>.ts` → register it in `src/index.ts` → add a case in `golden/cases.ts`, `npm run golden -- --update <name>` and look at the image → unit tests → give the block a `category` (`BlockCategory`), a gallery handle, and English and Japanese names and descriptions (one entry each in `apps/editor/src/i18n/blocks.en.ts` and `blocks.ja.ts`, keyed by type id; `apps/editor/src/i18n/blocks.test.ts` fails if one is missing) and English and Japanese names and descriptions for every parameter (`apps/editor/src/i18n/params.en.ts`, `params.ja.ts`, keyed `<type id>.<param key>`; a Chinese label of the form 「名稱（說明）」 is split into name + hint; `params.test.ts` fails if one is missing). The handle: add the next number of the category's prefix to `HANDLES` in `packages/protocol/src/handles.ts`, for example `MRK-08` (`tools/handles.test.ts` fails without one), and run `npm run blocks:index` (`guides/workflow.md` lists only the category index, details come from `catalog --find`; the test fails if the index is stale) → build:player + build:editor → all tests. A running server must be restarted before the gallery shows the new block. `npm run promote -- … --category <category>` assigns the handle and adds the category itself, and warns when the new name is only a letter or two away from an existing block. Sound effects have no promotion tool: the handle (`SFX-<category>-NN`) and the English and Japanese names and descriptions in `blocks.en.ts` / `blocks.ja.ts` (plus `params.en.ts` / `params.ja.ts` when it has parameters) are all added by hand.

**A block's `kind` decides whether it sits above or below the video**: `c.effect` always puts common `scene` blocks under the video (`layer: 'top'` is not allowed), and `overlay` above it. `scene` is only for pure backgrounds (paper, backdrop, shader) and frames whose text is all outside the video's window (frame, postcard); anything that cuts a hole for the video to play in and also draws text over the window (big titles, banners, quotes, darkening) must be `overlay`, like duo, casefile, magazine (magazine was mislabelled `scene` when promoted, so all its text was covered by the video; changed back 2026-10-25). Golden draws a block alone on the overlay track with no video under it, so it can't catch this: after promoting a block with a video window, run `tellcut -- frames` on a project that really has a clip in the window and look at a frame.

**Gallery handles** (`packages/protocol/src/handles.ts`): every shared block, sound effect, score style, recipe and clip effect has an `MRK-03`-style handle, used only for display and pointing (project.json and cut.ts still use type ids). Handles are permanent: a deleted block moves to `RETIRED`, one that changes category keeps its handle and is listed in `MOVED`; never renumber or reuse. Before promoting, `catalog --find` for similar blocks; if it can be a `look` of an existing block, don't make a new one; a new name is one English word that says what it looks like, with no number suffix.

**Cut API (`tools/cut/`)**: `projects/<id>/cut.ts` rebuilds the timeline from the footage and empty tracks every time, so it can be rerun. `cut.ts` is the `Cut` class itself; the work is split into `speech.ts` (captions, finding words), `tighten.ts` (cutting pauses), `mix.ts` (score, ducking) and `focus.ts` (framing faces, stickers that follow a face); recipes are in `tools/cut/recipes/` (travel / hook / montage / brand). The quick reference for Claude is generated by `npm run tellcut -- cut-api` (`api-doc.ts`), the block catalogue by `catalog` from `ItemType.doc` — remember the doc when adding a method or a block.

**Video genres (`guides/genres/`)**: `guides/genres/README.md` is the index and `guides/genres/<id>.md` one card per genre (English, for agents): what the storyboard must answer for that kind of film.

**media-node (`packages/media-node`)**: ffmpeg, footage analysis, transcription, burned-in text detection, faces, voice-over, score, export.
- Outside programs (ffmpeg, ffprobe, uv, Chrome, claude) are always found through `deps.ts` (`TELLCUT_*` environment variables → `vendor/` → install locations → PATH); the root constant is `TELLCUT_ROOT` in `paths.ts`.
- Analysis results are keyed by the footage's size + modification time; when another project has the same footage they are shared by hard link (`share.ts`); `transcript.lock` / `analysis.lock` prevent duplicate work.
- `project.json` is always written through `writeProjectFile` (old versions kept in `.history/`); the server's PUT uses ETag/If-Match.
- Which outside tool is used is set in `providers.json` (tts=edge, transcribe=faster-whisper, ocr=windows, faces=mediapipe), implemented in `media-node/src/providers/`, `tools/py/`, `tools/ps/`.
- Outside media sources are in `media-node/src/sources/`:
  - One folder per source, holding the adapter and its `card.md` (English, read by agents through `assets source <id>`).
  - Every request online goes through `http.ts` (identifying header, cross-process rate limiting, cache, block detection).
  - After download, `project.ts` registers the asset in the project and writes `media/assets.json` and `CREDITS.md`.
  - Maps are in `maps/`; tiles are stitched by `tools/py/map.py`.
  - The CLI is `tools/assets.ts` (`npm run tellcut -- assets …`); the health check is `npm run sources` (`--live` really downloads).
  - Switches: `sources.json` is in git and holds the defaults; `sources.local.json` holds the user's own switches, keys and `contact`, and is not in git. BBC, Incompetech and Steam (unofficial) are off by default.
  - The page chat also has per-conversation ticks: the ticks in the chat box's API menu stay on the page only and go with every message (the message's `sources`; the server keeps only that turn's, for the message sent automatically when analysis finishes; a reload or another conversation starts with nothing ticked); the runner hands them to the agent in the environment variable `TELLCUT_SOURCES`, and `assets` treats unticked sources as unavailable. Developer mode (CLI, batch) has no such variable and is not limited. Each adapter's `category` decides which group of the menu it is in.
  - A new source follows `SourceAdapter` and is added to `ADAPTERS` in `registry.ts`. The agents' instructions are in "Outside assets" in `guides/workflow.md`.

**Server (`apps/server`)**: routes are split into `src/*.ts` (each file starts with a description). The page chat (`src/chat/runner.ts`) starts one headless `claude` per message, with only an allowlist of tools and commands (`--allowedTools` in `runner.ts`) — this is a guard rail, not a sandbox: being able to write `cut.ts` or `fx/*.js` and then run `npm run cut` / export means being able to run any Node code, so the server only accepts page requests from its own address (Origin, Sec-Fetch-Site and CSP in `app.ts`), and the player only loads the project and fx from the project folder on the same server. Its system prompt is joined from three files every turn: `apps/server/chat-prompt.md` (the page chat's own rules), `guides/quality.md` (what makes a good film) and `guides/workflow.md` (the steps and tools for making a film, the same in every mode; any agent making films reads these two as well). These three, the genre cards in `guides/genres/`, and the prompts of the agent, skill and presets are all in English (everything agents read is in English); the tools' output is still Chinese, and docs quoting output keep the Chinese words. When the toolkit's usage changes, change workflow.md; it takes effect from the next message. The Claude in the chat never edits `project.json` directly: it writes `proposal.json` and sends a "proposal", which the user accepts in the editor.
→ **The page chat reads no CLAUDE.md, AGENTS.md or `.claude/rules`** (`claudeMdExcludes` in `apps/server/chat-settings.json`, passed by the runner with `--settings`; with `--setting-sources ""` that is the only settings file it loads, so a `tellcut/.claude/settings.json` never widens it), doesn't read or write auto memory, has no Agent / Skill tools, and its cache is fixed at 1 hour; its environment is given by the runner's `chatEnv` (it drops the `CLAUDE*` and `ANTHROPIC_API_KEY` the server inherits from a Claude Code session, plus the gateway and model settings `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`, `ANTHROPIC_*MODEL*`, and keeps the few used for signing in: `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_GIT_BASH_PATH`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK` / `VERTEX` / `FOUNDRY`; the default Bash timeout is 10 minutes, at most 30, and long commands stay in the foreground; `TELLCUT_CHAT_CACHE_TTL` changes the cache). Rules for it can only go in those three files; tellcut/CLAUDE.md is for developers.

**check (`tools/check/`)**: `rules.ts` looks only at the project model; `page.ts` / `visual.ts` run the built player and measure the picture (`__tellcut.layout()` measures text boxes); `burned.ts`, `leak.ts`, `letterbox.ts`, `edges.ts` and `stray.ts` handle the source's burned-in captions, bleeped words showing through, the source's own black bars, cuts that run into the neighbouring shot of the source, and the source's own text in the picture (OCR); `report.ts` lays out the report.

## Environment and caveats

- **Python only through tellcut's own uv environment**: `pyproject.toml` / `uv.lock`, `.venv/`, Python itself in `vendor/python`, models in `models/`. In code use media-node's `runUv` / `runPy` (`pythonEnv()`); by hand, `uv ... --project tellcut`. Never use the system Python or pip install; a bare `python -` or `python3` hangs.
- New outside dependencies: add them to `pyproject.toml` or `tools/setup/vendor.json` (with sha256) / `models.json`, and check them in `tools/setup/checks.ts`, so `npm run setup` can install them on another machine too (`npm run handover` exports only what is in git).
- **Restart the server with `npm run server:restart`** (`-- --port <port>` is optional: the default is the port of the one running, recorded in `.cache/server.json`, else 5174; a server started by hand on another port records itself there too, so after running a test server pass the user's port): it first makes sure no chat turn or analysis job is running (refuses if one is; `--wait` waits for them), stops the process listening on that port, then starts it again in the background with a clean environment (log in `.cache/server-<port>.log`). Running `npm run server` directly from Claude Code makes child processes other than the page chat carry the session's environment variables. When restarting by hand, likewise first make sure no chat turn or analysis job is running (`running` is null in each project's `GET /api/chat/<id>`, and `GET /api/jobs` has no analyze/extras in progress) — the user may be testing in the browser. After stopping the npm wrapper, the node child process listening on the port is still there and must be stopped too. A running server locks esbuild.exe; stop it before `npm ci`.
- PowerShell 5.1 mangles double quotes inside here-strings: when a commit message has quotes, use `git commit -F <file>`; `Out-File` utf8 adds a BOM, so write JSON with node or bash (`tools/ps/ocr.ps1`, on the contrary, must have a BOM). With `node -e`, don't put single quotes in the content; write longer patch scripts as a `.cjs` file in the scratchpad and run that.
- In Playwright, call `page.bringToFront()` before judging whether the player plays; otherwise rAF in a background tab runs at only 1–2 fps.
- `projects/_*` (`_home` the home-page chat, `_gallery`, `_golden`) are not video projects and are not in git. The project folders under `projects/` all belong to the user; none of them goes into git, so never include them in a commit. Tests that need a real project's format read the copies in `tools/fixtures/` (only project.json and its fx, no footage).
- Test temp folders: `tools/test-cleanup.ts` (vitest globalSetup) makes its own `tellcut-test-XXXXXX` in the system temp folder on every run, points `TEMP` / `TMP` / `TMPDIR` at it, and deletes only that one when done; two test runs at once don't delete each other's. Leftovers from an earlier run (whose process is gone) are cleaned by the next run.

## Working habits

- Never kill processes by image name (`taskkill /IM python.exe`, `node.exe`, `chrome.exe`): that also kills the user's server, transcriptions and other sessions. Stop only the PIDs you started.
- Restart the server with `npm run server:restart` (see "Environment and caveats" above), not with `Start-Process` or `npm run server` directly from Claude Code.
