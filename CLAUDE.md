# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Tellcut: a video editor used in a local browser (Node 24 + TypeScript, **Windows and macOS**), plus a "generation toolkit" for Claude (new → inspect → cut → check → export). How to use it, the full command table and the project folder format are in [docs/reference.md](docs/reference.md) (the README is the introduction for everyone); this file only covers what is hard to see from reading the code.

- The git root is `tellcut/` itself (branch `main`); commit paths have no `tellcut/` prefix.
- Code comments that cite a "spec 2026-…", a review code (R3-…, review2 B3) or a phase point to the maintainers' design notes, which are not in this repo; the comment itself should still say why.
- Public docs are in English; code comments are in English. The exceptions are the translated READMEs, `README.zh-TW.md` (Traditional Chinese) and `README.ja.md` (Japanese): keep them in sync with `README.md` (change one, change them all; their language bars link each other). In `README.ja.md`, use the Japanese UI's own words for presets and buttons (`ja.ts`, the presets' `name.ja`), and English for the editor's labels. Pictures for the README are in `docs/readme/` (sources in `docs/readme/CREDITS.md`). UI text goes through the three dictionaries in `apps/editor/src/i18n/` (zh / en / ja, with the same keys; the editor's labels are always English, while hints, tips and status text follow the language); never hard-code text in a component. The page chat replies in the UI language.

## Common commands

```
npm run server                         # http://127.0.0.1:5174/editor/ (local connections only; -- --port 5200 for another port)
npm test                               # everything: the fast group, then the browser group (tools/test-all.mjs, see vitest.workspace.ts)
npm run test:fast                      # the group that needs no Chrome; run this first after a change
npm run test:browser                   # export, check's picture layer, golden, editor e2e (at most two files at once)
npx vitest run tools/cut/cut.test.ts   # one test file; add -t "<name>" for one case
npm run typecheck
npm run build:player && npm run build:editor
npm run golden -- [--update <name prefix>] # golden images of the shared blocks; --update takes one prefix at a time, and look at the images after updating
npm run thumbs                            # the gallery's English and Japanese thumbnails (after build:player; tools/thumbs.test.ts says when; Windows only)
npm run setup / npm run doctor         # install the outside dependencies into vendor/, .venv, models/; when the environment misbehaves, run doctor first
```

## Architecture

**One player, four uses.** `apps/player` is the only picture implementation: the editor preview (an iframe, the project passed in by postMessage), export, `check`'s picture layer and the golden images all run it. Export: `media-node/prepare.ts` first trims the pieces the project uses into `projects/<id>/cache/`; `media-node/render.ts` serves the tellcut folder with a static server, opens the player with `?mode=render` in headless Chrome, calls `window.__tellcut.frame(n)` frame by frame and feeds the screenshots to ffmpeg; the WebAudio mix is rendered offline and then muxed into the MP4.
→ **After changing `packages/*/src` or `apps/player/src`, always `npm run build:player`**: export, check, frames and golden all use the built files. Without a rebuild, golden falsely reports "all match"; check rebuilds by itself when it finds the build out of date (`staleness.ts`: the sources, `public/` and `vite.config.ts`; about 4 s; `--quick` doesn't), and only reports an error if the rebuild fails. Both go through media-node's `rebuildPlayer` (`tools/build-player.ts`): built in `.cache/` and moved into `dist/` file by file under a lock, never vite's emptying of `dist/` (an export or check loading the player meanwhile got font 404s). `npm run build:editor` (`tools/build-editor.ts`) does the same for the editor, so a running server keeps serving it during a build; both share media-node's `build-swap.ts` (index.html moves last; the previous build's files stay one more build for pages that loaded the old index.html).

**Engine (`packages/engine`)**: `schema.ts` (zod, the single source of truth for `project.json`), the `stage.ts` compositor (one layer per item; `draw(t)` is a pure function of t — a block may not depend on the previous frame's state or on randomness; check draws the same time twice and compares PSNR), `motion.ts` the springs and easings every item gets as `ctx.motion` (thin wrappers over motion-dom / motion-utils, in seconds; Motion's `animate()` is not used, it runs on the frame loop and lags a seek by one rAF), `commands/` the edit commands, `audio/` the mix plan.

**Blocks (ItemType, interface in `engine/src/plugin.ts`) come in three layers:**
1. core: `engine/src/core.ts`
2. common: `packages/plugin-common` (`common.*`, DOM text, sized by min(W,H)/1080 (exception: the font sizes of `common.caption`, `common.heading`, header, meter, progress, slam, stamp, tag and tripclock are a percentage of the frame height, and their labels say 「畫面高 %」), positioned within the theme's safe area)
3. a project's own fx: `projects/<id>/fx/*.js` — plain ES modules, default export `ItemType[]`, ids `fx.*`, **may not import packages**, listed in `project.json`'s `meta.fx`; loaded in the browser by `plugins/src/browser-fx.ts` and in Node by media-node.

**3D (three.js)**: blocks and fx that use three are marked `three: true` and get the toolkit from `ctx.three` (`ThreeKit` in `plugin-common/src/three/kit.ts`: the shared renderer, video textures, `coverUv`, `fillDistance`, the ready-made parts of `three/parts.ts`: `videoSlab`, `glassBar`, `dust`, `floor`, and of `three/marks.ts` for a logo from the user's file: `loadMark`, `svgMark`, `pictureMark`, `word3d`). three is only loaded dynamically in `plugin-common/src/three/load.ts`, and the player loads it only when `usesThree` is true (the main chunk has no three; `three/imports.test.ts` guards this). Blocks that read video frames upload the texture in `late()` (`drawFrame`: draw → wait for the video to seek → late); GPU resources are freed in `dispose(state)` (called when the stage drops an item: rebuild after an edit, delete, switching project), while `hide` only lets go of the canvas; video textures are always drawn to a 2D canvas first, because headless Chrome gives WebGL a black `<video>` directly.

`packages/plugins` is the one plugin list shared by player, editor, server and tools. Parameter precedence: item params > the project theme (the path `ParamDef.theme` points to) > the default.

**Promoting fx to a shared block** (`npm run promote` does the moving, registering, handle and golden case, and rewrites the project's project.json and `cut.ts` to the new id; from an fx file of several blocks it moves only the one named (`tools/fx-split.ts`): the shared file gets that block and the top-level helpers it still names, the project's file keeps the others with that entry taken out of its `export default [ … ]`, along with the top-level helpers only that entry used (directly or through another such helper; imports, exports, statements that run something and helpers already unused before stay), and stays in `meta.fx` and in `cut.ts`; it splits only an export written as an array literal of `{ type: '…', … }` objects and refuses, writing nothing, when it cannot (another shape, a type it loads as but does not say, a result that does not parse or would miss a name); the project's file as it was is kept in `.history/promote/`; the steps below it leaves to you are the i18n texts, the golden picture, `blocks:index` and the builds): write `packages/plugin-common/src/<name>.ts` → register it in `src/index.ts` → add a sample in `src/samples.ts` (its golden case; the first one is also its gallery thumbnail), `npm run golden -- --update <name>` and look at the image (on a Mac this writes only `golden/darwin/`: the shared picture comes from an update on Windows) → unit tests → give the block a `category` (`BlockCategory`), a gallery handle, and English and Japanese names and descriptions (one entry each in `apps/editor/src/i18n/blocks.en.ts` and `blocks.ja.ts`, keyed by type id; `apps/editor/src/i18n/blocks.test.ts` fails if one is missing) and English and Japanese names and descriptions for every parameter (`apps/editor/src/i18n/params.en.ts`, `params.ja.ts`, keyed `<type id>.<param key>`; a Chinese label of the form 「名稱（說明）」 is split into name + hint; `params.test.ts` fails if one is missing), and the words of every parameter whose default is Chinese in English and Japanese (`values.en.ts`, `values.ja.ts`, same keys, same lines and `|` fields as the default; a block added in the English or Japanese UI starts with them; `values.test.ts` fails if one is missing); then `npm run build:player` and `npm run thumbs`, which draws the gallery's English and Japanese thumbnails into `golden/thumbs/` (`tools/thumbs.test.ts` fails when they are out of date; Windows only, like the shared golden pictures: on a Mac it refuses). The handle: add the next number of the category's prefix to `HANDLES` in `packages/protocol/src/handles.ts`, for example `MRK-09` after `MRK-08` (`tools/handles.test.ts` fails without one), and run `npm run blocks:index` (`guides/workflow.md` lists only the category index, details come from `catalog --find`; the test fails if the index is stale) → build:player + build:editor → all tests. A running server must be restarted before the gallery shows the new block. `npm run promote -- … --category <category>` assigns the handle and adds the category itself, and warns when the new name is only a letter or two away from an existing block. Sound effects have no promotion tool: the handle (`SFX-<category>-NN`) and the English and Japanese names and descriptions in `blocks.en.ts` / `blocks.ja.ts` (plus `params.en.ts` / `params.ja.ts` when it has parameters) are all added by hand.

**A block's `kind` decides whether it sits above or below the video**: `c.effect` always puts common `scene` blocks under the video (`layer: 'top'` is not allowed), and `overlay` above it. `scene` is only for pure backgrounds (paper, backdrop, shader) and frames whose text is all outside the video's window (the old frame and postcard, now hidden behind common.flatlay); anything that cuts a hole for the video to play in and also draws text over the window (big titles, banners, quotes, darkening) must be `overlay`, like duo, casefile, magazine (magazine was mislabelled `scene` when promoted, so all its text was covered by the video; changed back 2026-10-25). Golden draws a block alone on the overlay track with no video under it, so it can't catch this: after promoting a block with a video window, run `tellcut -- frames` on a project that really has a clip in the window and look at a frame.

**Parameter names for new blocks.** Older blocks are not consistent and keep their names (renaming would need an alias for every old project), but a new block follows these: `x` / `y` are the centre, as a fraction of the frame's width / height (an edge gets its own key, `left` / `top`); `size` is a percentage of the frame's short side (only the text blocks listed under common above use the frame height), and a plain multiplier is `scale`; `look` picks one of the block's looks (what it looks like), `mode` changes what it does (`emoji`'s `cover`), and there is no `style`, `kind` or `variant` beside them; the entrance and exit are `enter` / `exit`. Say the unit in the Chinese label (「畫面短邊 %」, 「畫面寬比例」).

**Gallery handles** (`packages/protocol/src/handles.ts`): every shared block, sound effect, score style, recipe and clip effect has an `MRK-03`-style handle, used only for display and pointing (project.json and cut.ts still use type ids). Handles are permanent: a deleted block moves to `RETIRED`, one that changes category keeps its handle and is listed in `MOVED`; never renumber or reuse. Before promoting, `catalog --find` for similar blocks; if it can be a `look` of an existing block, don't make a new one; a new name is one English word that says what it looks like, with no number suffix.

**Cut API (`tools/cut/`)**: `projects/<id>/cut.ts` rebuilds the timeline from the footage and empty tracks every time, so it can be rerun. `cut.ts` is the `Cut` class itself; the work is split into `tighten.ts` (cutting pauses), `mix.ts` (score, ducking), `focus.ts` (framing faces, stickers that follow a face) and `frames.ts` (an item's frame and shape, the main-track clip under a flatlay object), while the caption plan (captions from speech, finding words) is `packages/plugin-common/src/speech.ts` (`@tellcut/plugin-common/speech`), shared with the editor; recipes are in `tools/cut/recipes/` (travel / hook / montage). The quick reference for Claude is generated by `npm run tellcut -- cut-api` (`api-doc.ts`), the block catalogue by `catalog` from `ItemType.doc` — remember the doc when adding a method or a block.

**My blocks and my presets** (`docs/reference.md` "My blocks and my presets"): the user's own library is `projects/_library/`, read and written only through `media-node/src/library/` (the routes in `apps/server/src/library.ts` and `npm run tellcut -- library` share it). An entry is used by **copying** it into the project's `fx/lib/<slug>/` (`useBlock`; `meta.fx` names the copy's `_entry.js`, a re-export that keeps its name across updates): never load a module from outside the project folder (`browser-fx.ts` / `loadProjectFx` refuse it on purpose). A preset of the user's own (`projects/_presets/my-*`, `preset-write.ts`) has `points` (`{ text, prompt }`) as its whole prompt, so the page never shows a point it does not send. Caption and title looks saved as My templates (`projects/_library/captions/`, `titles/`) are copied the same way, into `meta.captionTemplates` / `meta.titleTemplates` under `my-<slug>-<hash>`. Buttons that need the agent send a chat `task` worded by `apps/server/src/chat/tasks.ts`.

**Video genres (`guides/genres/`)**: `guides/genres/README.md` is the index and `guides/genres/<id>.md` one card per genre (English, for agents): what the storyboard must answer for that kind of film. A preset with `"genres": false` replaces them (see `docs/reference.md`).

**media-node (`packages/media-node`)**: ffmpeg, footage analysis, transcription, burned-in text detection, faces, voice-over, score, export.
- Outside programs (ffmpeg, ffprobe, uv, Chrome, claude) are always found through `deps.ts` (`TELLCUT_*` environment variables → `vendor/` → install locations → PATH); the root constant is `TELLCUT_ROOT` in `paths.ts`.
- Analysis results are keyed by the footage's size + modification time + its path within the project (`hash.ts` `sourceHash`: two files of one size and time are not one file); when another project has the same footage they are shared by hard link (`share.ts`), and so are those of footage renamed or moved since (a folder's `source.json` names its file and a print of a few slices of it, compared before sharing: two different files of one size and time never share); `transcript.lock` / `analysis.lock` prevent duplicate work between processes; within one server, `analysis.ts` keeps a list of the analyses in progress by footage, so two projects given the same new file at once make it once and the later one links to it.
- `project.json` is always written through `writeProjectFile` (old versions kept in `.history/`); the server's PUT uses ETag/If-Match.
- Which outside tool is used is set in `providers.json` (tts=edge, or elevenlabs with a key from `ELEVENLABS_API_KEY` / `keys.elevenlabs` in `sources.local.json`; transcribe=faster-whisper, ocr=system — Windows' own or macOS' Vision, faces=mediapipe), implemented in `media-node/src/providers/`, `tools/py/`, `tools/ps/`, `tools/mac/`.
- Outside media sources are in `media-node/src/sources/`:
  - One folder per source, holding the adapter and its `card.md` (English, read by agents through `assets source <id>`).
  - Every request online goes through `http.ts` (identifying header, cross-process rate limiting, cache, block detection). The server's start-up cleanup removes cached answers, thumbnails and contact sheets in `.cache/sources/` older than 30 days (`pruneSourceCache`); search thumbnails give up after 20 s.
  - After download, `project.ts` registers the asset in the project and writes `media/assets.json` and `CREDITS.md`.
  - Maps are in `maps/`; tiles are stitched by `tools/py/map.py`.
  - The CLI is `tools/assets.ts` (`npm run tellcut -- assets …`); the health check is `npm run sources` (`--live` really downloads).
  - Switches: `sources.json` is in git and holds the defaults; `sources.local.json` holds the user's own switches, keys and `contact`, and is not in git. BBC, Incompetech and Steam (unofficial) are off by default.
  - The page chat also has per-conversation ticks: the ticks in the chat box's API menu stay on the page only and go with every message (the message's `sources`; the server keeps only that turn's, for the message sent automatically when analysis finishes; a reload or another conversation starts with nothing ticked); the runner hands them to the agent in the environment variable `TELLCUT_SOURCES`, and `assets` treats unticked sources as unavailable. Developer mode (Claude Code on the command line) has no such variable and is not limited. Each adapter's `category` decides which group of the menu it is in.
  - A new source follows `SourceAdapter` and is added to `ADAPTERS` in `registry.ts`. The agents' instructions are in "Outside assets" in `guides/workflow.md`.

**Server (`apps/server`)**: routes are split into `src/*.ts` (each file starts with a description). The page chat (`src/chat/runner.ts`) starts one headless `claude` per message, with only an allowlist of tools and commands (`--allowedTools` in `runner.ts`) — this is a guard rail, not a sandbox: being able to write `cut.ts` or `fx/*.js` and then run `npm run cut` / export means being able to run any Node code, so the server only accepts page requests from its own address (Origin, Sec-Fetch-Site and CSP in `app.ts`), and the player only loads the project and fx from the project folder on the same server. Its system prompt is joined from three files every turn: `apps/server/chat-prompt.md` (the page chat's own rules), `guides/quality.md` (what makes a good film) and `guides/workflow.md` (the steps and tools for making a film, the same in every mode; any agent making films reads these two as well). These three, the genre cards in `guides/genres/`, and the presets' prompts are all in English (everything agents read is in English); the tools' output is still Chinese, and docs quoting output keep the Chinese words (except the install path: `setup`, `doctor` and `examples` print English, for people who have just cloned Tellcut). When the toolkit's usage changes, change workflow.md; it takes effect from the next message. The Claude in the chat never edits `project.json` directly: it writes `proposal.json` and sends a "proposal", which the user accepts in the editor.
→ **The page chat reads no CLAUDE.md, AGENTS.md or `.claude/rules`** (`claudeMdExcludes` in `apps/server/chat-settings.json`, passed by the runner with `--settings`; with `--setting-sources ""` that is the only settings file it loads, so a `tellcut/.claude/settings.json` never widens it), doesn't read or write auto memory, has no Agent / Skill tools, and its cache is fixed at 1 hour; its environment is given by the runner's `chatEnv` (it drops the `CLAUDE*` and `ANTHROPIC_API_KEY` the server inherits from a Claude Code session, plus the gateway and model settings `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`, `ANTHROPIC_*MODEL*`, and keeps the few used for signing in: `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_GIT_BASH_PATH`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK` / `VERTEX` / `FOUNDRY`; the default Bash timeout is 10 minutes, at most 30, and long commands stay in the foreground; `TELLCUT_CHAT_CACHE_TTL` changes the cache). Rules for it can only go in those three files; tellcut/CLAUDE.md is for developers.

**check (`tools/check/`)**: `rules.ts` looks only at the project model; `page.ts` / `visual.ts` run the built player and measure the picture (`__tellcut.layout()` measures DOM text boxes plus the words items report drawing on a canvas with `ctx.reportText`, engine `report.ts`, kept only in the player's render mode; shared blocks that draw words on a canvas keep a transparent DOM copy instead, `plugin-common/src/text.ts` ghostLine); `burned.ts`, `leak.ts`, `letterbox.ts`, `edges.ts` and `stray.ts` handle the source's burned-in captions, bleeped words showing through, the source's own black bars, cuts that run into the neighbouring shot of the source, and the source's own text in the picture (OCR); `report.ts` lays out the report.

## Environment and caveats

- **Python only through tellcut's own uv environment**: `pyproject.toml` / `uv.lock`, `.venv/`, Python itself in `vendor/python`, models in `models/`. In code use media-node's `runUv` / `runPy` (`pythonEnv()`); by hand, `uv ... --project tellcut`. Never use the system Python or pip install; a bare `python -` or `python3` hangs.
- New outside dependencies: add them to `pyproject.toml` or `tools/setup/vendor.json` (one build per system under `builds`, keyed `<platform>-<arch>` or `<platform>`, each with its sha256; a program with no build for a system is not downloaded there) / `models.json`, and check them in `tools/setup/checks.ts`, so `npm run setup` can install them on another machine too (a fresh clone has only what is in git).
- **macOS** (Windows' code paths are unchanged; each place that talks to the system has a branch for both): process trees end through media-node's `killTree` (`proc.ts`: taskkill /T on Windows, the tree read from `ps` and signalled elsewhere; never a detached group, which a Ctrl+C of the server would leave running; `proc.ts` also holds `isAlive`, `nap`, `pause` and `shellQuote`, and its platform, kill and `ps` are injectable (`ProcEnv`, the `platform` arguments, server-restart's `Stopper`) so the macOS branches are tested on Windows too); OCR is `"use": "system"` in `providers.json` (Windows.Media.Ocr, or Apple's Vision through `tools/mac/ocr.swift`, built with `swiftc` into `.cache/bin/ocr-vision-<hash>` on first use); setup downloads only uv there, and ffmpeg is Homebrew's keg-only `ffmpeg-full`, found in its opt folder ahead of PATH (the plain `ffmpeg` formula has neither vid.stab nor drawtext; doctor checks the vid.stab filters); `server:restart` uses `lsof` and a detached node. `transcribe.py` leaves with `os._exit` there (onnxruntime can hang in its exit teardown on macOS), and a transcription whose JSON is whole but whose Python has not exited after 30 s is ended (`runUv`'s `done`). In exports the macOS page is 200 px taller than the stage and each capture is clipped to it (headless Chrome there paints 87 px short), and Chrome runs with `--use-angle=metal` (no WebGL otherwise): blocks and fx size from the stage, never from the window. Golden pictures that macOS draws differently (CoreText, Apple's emoji) are kept in `packages/plugin-common/golden/darwin/`; a Mac matches either those or the shared ones and its update never writes the shared ones. Tests that need a Windows feature skip elsewhere and the reverse.
- **Restart the server with `npm run server:restart`** (`-- --port <port>` is optional: the default is the port of the one running, recorded in `.cache/server.json`, else 5174; a server started by hand on another port records itself there too, so after running a test server pass the user's port): it first makes sure no chat turn or analysis job is running (refuses if one is; `--wait` waits for them), stops the process listening on that port, then starts it again in the background with a clean environment (log in `.cache/server-<port>.log`). Running `npm run server` directly from Claude Code makes child processes other than the page chat carry the session's environment variables. When restarting by hand, likewise first make sure no chat turn or analysis job is running (`running` is null in each project's `GET /api/chat/<id>`, and `GET /api/jobs` has no analyze/extras in progress, nor an `import` or `preset`: a file being dropped in, a HEIC conversion, a preset's poster) — the user may be testing in the browser. After stopping the npm wrapper, the node child process listening on the port is still there and must be stopped too. A running server locks esbuild.exe; stop it before `npm ci`.
- PowerShell 5.1 mangles double quotes inside here-strings: when a commit message has quotes, use `git commit -F <file>`; `Out-File` utf8 adds a BOM, so write JSON with node or bash (`tools/ps/ocr.ps1`, on the contrary, must have a BOM). With `node -e`, don't put single quotes in the content; write longer patch scripts as a `.cjs` file in the scratchpad and run that.
- In Playwright, call `page.bringToFront()` before judging whether the player plays; otherwise rAF in a background tab runs at only 1–2 fps.
- `projects/_*` (`_home` the home-page chat, `_gallery`, `_golden`) are not video projects and are not in git. The project folders under `projects/` all belong to the user; none of them goes into git, so never include them in a commit. Tests that need a real project's format read the copies in `tools/fixtures/` (only project.json and its fx, no footage).
- Test temp folders: `tools/test-cleanup.ts` (vitest globalSetup) makes its own `tellcut-test-XXXXXX` in the system temp folder on every run, points `TEMP` / `TMP` / `TMPDIR` at it, and deletes only that one when done; two test runs at once don't delete each other's. Leftovers from an earlier run (whose process is gone) are cleaned by the next run. The tests that really transcribe use the small `tiny` speech model (`tools/test-env.ts` sets `TELLCUT_WHISPER_MODEL` unless it is set; `npm run setup` installs it, else the first test run downloads it). The same file pins every run to the `Asia/Taipei` time zone (`TZ`, set even when one is): footage times read from a UTC tag become local time while a photo's EXIF time has none, so expected values written in one zone fail in another. `.cache/test-workers.log` records which file each test worker ran and its exit code (`tools/test-workers.ts`): when a full run reports "Worker exited unexpectedly", look there; 3221226505 (0xC0000409) is the fail-fast older Node 24 (24.15 and before) does on Windows now and then when a server is started and closed so often the dynamic ports run out, no fault of the test; Node 24.22.2 and 26.13.0 no longer do it. `setup` and `doctor` warn (a `!` row, still ok) on Windows below those (`nodeFailFastFix` in `tools/setup/checks.ts`).

## Working habits

- Never kill processes by image name (`taskkill /IM python.exe`, `node.exe`, `chrome.exe`): that also kills the user's server, transcriptions and other sessions. Stop only the PIDs you started.
- Restart the server with `npm run server:restart` (see "Environment and caveats" above), not with `Start-Process` or `npm run server` directly from Claude Code.
- A new command-line tool reads its flags with `tools/args.ts` (`parseArgs` / `parseArgsOrExit`, each flag declared as a switch, a value or a list; `maxWords` refuses words too many), so a mistyped flag is refused instead of eating the next word; its top-level catch goes through `printFailure` (`--help` on stdout with exit 0, a usage error on stderr with 2, anything else 1).
